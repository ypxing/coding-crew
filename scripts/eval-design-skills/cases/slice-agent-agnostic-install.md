## Request
PRD #536 (below) is approved; the feature slug is `agent-agnostic-install`, under `tracker: github`. Break it into issues. The PRD body, as first published:

Feature: agent-agnostic-install

## Problem Statement

Actor: a developer who uses a coding agent other than Claude Code, Copilot CLI, Codex CLI or pi, and the maintainer who wants coding-crew to reach them.
Origin: #490

The skills are agent-agnostic (no file under `skills/` or `lib/` names a CLI; the only hits are `CLAUDE.md`/`AGENTS.md` reads), but the install is not. `platforms.json` names four CLIs, and `install.sh` is the only thing that can produce a working skill: it expands 18 `{{FRAGMENT:…}}` lines in 8 SKILL.md files at install time (`scripts/render-skill.sh`) and creates the 20 `<skill-dir>/scripts/<lib>` links that `registry.json` `libs` names (`install.sh:246` `install_lib`, `:273` `link_lib`). Any other installer ships instruction holes and no tracker CLI. `npx skills add` (vercel-labs/skills 1.7.2) targets 79 agents and already finds all 17 skills here, but installs them broken for that reason. Cost today: unrealized reach, not a measured failure (no outside issue asks for another agent; an all-states search for cursor/gemini/opencode/windsurf/cline/kiro/amp/droid returns only the maintainer's PRD #306).

## Solution

The committed tree is the installed tree. Every SKILL.md is committed with its fragments expanded in place, and every library a skill uses is committed as a copy inside that skill's `scripts/`, both written by one script and guarded by a test that fails when a copy is stale. `npx skills add ypxing/coding-crew --all` then installs working skills into any of 79 agents, `install.sh` copies the same directories verbatim for the four it knows, and `.coding-crew/lib` disappears. The README leads with the npx route, states that the `codex` target is the shared `.agents/skills` location some 25 agents read, and keeps `bootstrap.sh` for what it alone does. One real crew-afk run from an `npx skills` install proves the route before the README advertises it.

## Behaviours

- **B1** — given a fresh checkout, `npx -y skills@1.7.2 add <checkout> --all` into a temp HOME installs all 17 skills, no installed SKILL.md contains `{{`, and `node <skills-dir>/solve-issue/scripts/tracker/cli.mjs config` prints `tracker=local`, at a bats test
- **B2** — given a committed SKILL.md or lib copy that differs from what the render script would write, a bats test fails naming the file, at `bats tests/`
- **B3** — given `install.sh <platform>` at either scope, each installed `<skills-dir>/<name>/` is a byte-for-byte copy of `skills/<name>/`, no `.coding-crew/lib` exists, and `cli.mjs config` runs from the installed `scripts/tracker/`, at the golden install tests and `tests/install.bats`
- **B4** — given a manifest an older install wrote with a `libs` list, `uninstall.sh` and `install.sh --update` remove the `.coding-crew/lib/<lib>` dirs it lists and keep `config.json`, at `tests/install.bats`
- **B5** — given a `ready-for-human` issue, its "Mark it done" step and Undo tell the person to have their coding agent run the tracker CLI op, and name no `.coding-crew/lib` path, at the diff of `skills/_shared/fragments/human-issue.md` and the rendered `to-issues`/`to-prd` SKILL.md
- **B6** — given `scripts/smoke-crew-afk.sh claude --via npx`, the demo repo is set up from `npx skills add <checkout>` instead of `install.sh`, and the log still ends `SMOKE: PASS (claude, demo)`, which `cut-release.sh:72` accepts, at `tests/smoke-crew-afk.bats`
- **B7** — given the README, its first install command is the npx route and it names the agents that read `.agents/skills`, at the README diff

## Decisions

- **D1** — Both routes (crew-grill Q1c): the committed tree installs as-is through `npx skills add` (79 agents), and the README states that the `codex` target in `platforms.json` (`.agents/skills` at both scopes) is the de facto shared location, read by Codex, Copilot, pi, Cursor, Gemini CLI, OpenCode, Amp, Devin, Cline, Goose, Factory, Junie, Zed, Augment, Warp, Qwen Code, Kimi, Mistral Vibe, Crush, Kilo, Hermes, Codebuff, Rovo Dev and Zencoder (the agentskills.io spec defines no discovery location; each vendor's docs or source confirms its own). Holdouts that read neither `.agents/skills` nor `~/.agents/skills`: Claude Code (issue anthropics/claude-code#66352 closed not-planned), Kiro, Continue. The `codex` key keeps its name `(auto)`.
- **D2** `(auto)` — Fragments are expanded **in place** in the committed SKILL.md between `<!-- fragment:<key> -->` and `<!-- /fragment:<key> -->` marker lines; the text between them is the fragment file's content and is never edited by hand. The 18 `{{FRAGMENT:<key>}}` lines in 8 files (`grep -rn "{{FRAGMENT:" skills --include=SKILL.md`) become marker pairs once. `scripts/render-skill.sh` (today: `{{FRAGMENT}}` → fragment text, stdout or outfile) becomes the tree renderer: for every skill it refreshes the text between markers and copies `lib/<name>/` to `skills/<skill>/scripts/<name>/` for each name in that skill's `registry.json` `libs` (an exact copy: files the source no longer has are removed). It takes no platform. A missing fragment file or an unmatched marker is a hard error, as today's missing fragment is (`render-skill.sh:49-52`).
- **D3** `(auto)` — Libraries are committed as **copies**, not symlinks: `skills` 1.7.2's project lock hash visits only files and directories (`src/local-lock.ts:182-186`), so a lib-only change behind a link would never trigger `npx skills update`, and Git for Windows checks repo symlinks out as text files. Size: checks 7 uses × 104K, tracker 11 × 120K, git-workflow 2 × 12K ≈ 2.0 MB (`registry.json`, `du -sk lib/*`). `.gitattributes` marks `skills/*/scripts/{checks,tracker,git-workflow}/**` `linguist-generated=true` so PR diffs collapse them; the reviewer subagent reads the diff, and 11 duplicate tracker hunks would waste its context. `lib/` stays the only source anyone edits; `CLAUDE.md` gets the render command, and `docs/guide.md:132`'s "never inline a fragment by hand" rule becomes "never edit between markers or under `scripts/<lib>/`: run the renderer".
- **D4** — A test fails when any committed render output is stale: it runs the renderer into a temp copy and diffs against the tree (B2). `tests/render-skill-shared-fragments.bats` (7 tests on `{{FRAGMENT}}` rendering, `:35-103`) and `tests/helpers/render.bash` (renders bodies for other suites, with a content-hash cache) are rewritten against the committed bodies: the rendered body is now the file in the tree. `tests/native-skills.bats:18-33`'s path scan (`find skills -type f`) must skip `skills/*/scripts/<lib>/` copies, or every lib file is scanned as skill prose. `tests/install.bats:213` ("the libraries are not in skills/") asserts the opposite of D3 and is replaced.
- **D5** — `npx skills` route, proven by a bats test (B1) that runs a **pinned** `npx -y skills@1.7.2 add <checkout> --all -g` with `HOME` set to a temp dir (the tool installs from a local path: `src/add.ts:1150,1618`; it clones GitHub sources, copies with `cp … dereference: true` (`src/installer.ts:541-543`), keeps exec bits, follows no inter-skill dependencies, and writes once to `.agents/skills/<name>` linking non-universal agents' dirs to it, only when the agent's root dir exists for a project install (`src/installer.ts:100,422`)). Network is required, as today's install tests require `jq`. Set `DISABLE_TELEMETRY=1` in the test.
- **D6** — `install.sh` copies `skills/<name>/` verbatim (crew-grill Q2b): `install_single_skill` (`install.sh:298`) keeps the per-file copy, the prune and the `deps` recursion, and loses the render step (`:341-346`), the libs loop, `link_lib`, `install_lib` (`:246-296`), the "exists, but the library is linked" guard (`:372`) and the manifest's `libs` (`write_manifest`, `:490`). `LIB_DEST` stays only in uninstall's migration (D7). What relied on the old layout: the goldens (`tests/fixtures/platform-golden/install/*`, 24 files, regenerated with `UPDATE_GOLDEN=1`), `tests/install.bats` tests at `:26,160,175,223,252,291,628,637,649,657,667,676`, `tests/platform-install.bats` (3 hits), `tests/dep-install-assets.bats` (7), `tests/solve-issue-scripts.bats`, `tests/setup-coding-crew.bats`, `tests/solve-feature.bats` (3-4 each), `scripts/smoke-crew-afk.sh:93-95` (`.worktreeinclude` and `.git/info/exclude` list `.coding-crew/lib`), and the runtime reads nothing there: `lib/` and `skills/*/scripts` read only `.coding-crew/config.json` (`lib/tracker/tracker-config.mjs:10`, `skills/solve-feature/scripts/solve-feature.sh:105`) and `.coding-crew/dev-commands.json` (`lib/checks/commands-file.sh:8`).
- **D7** — Migration of `.coding-crew/lib`: `uninstall.sh`'s `update_manifest`/`remove_lib` (`uninstall.sh:163-186`) already removes each lib dir an existing manifest lists and `prune_coding_crew_dirs` keeps `config.json`; that path stays so an old manifest's `libs` are removed on `uninstall.sh` and on `install.sh --update` (which uninstalls first). A new manifest writes no `libs`; `manifest_list libs` on it is empty. Every exit path of install leaves `config.json` and `dev-commands.json` untouched, as today.
- **D8** — The human "Mark it done" step names the op, not a path (crew-grill Q3a, wording `(auto)`): "Tell your coding agent: run the coding-crew tracker CLI (`scripts/tracker/cli.mjs` inside any coding-crew skill, e.g. `solve-issue`) with `mark-done <n>`"; its Undo: the same with "Reopen an issue" from the tracker doc beside that `cli.mjs`. Naming the CLI keeps the one-writer rule (`CLAUDE.md`: an agent never edits `Status:` directly). Assumption the user accepted: whoever does a human issue has an agent with coding-crew installed. Lines that change: `skills/_shared/fragments/human-issue.md:14-16,54-57`, `lib/tracker/docs/local.md:16,25`, `lib/tracker/docs/github.md:18,26`, `lib/git-workflow/README.md:15`, `docs/guide.md:49-50,175,257,367-368,439`, `.github/copilot-instructions.md:46,53-54`, `skills/setup-coding-crew/hosts/github-actions.yml:129-130` (comment).

Three one-line caveats: a project install writes `skills-lock.json` to commit; Claude Code's project link is created only when `.claude/` already exists; the tool sends telemetry to skills.sh unless `DISABLE_TELEMETRY` is set. The four badges and the "Agent-agnostic" bullet (`README.md:10-13,92`) change to say any agent that loads Agent Skills, with the four as the ones smoke-tested. `docs/guide.md`'s install section (`:147-168`) follows.

## Compatibility & Migration

- Install layout: `<skills-dir>/<name>/scripts/<lib>` changes from a link into `.coding-crew/lib/<lib>` to a real directory; `.coding-crew/lib` is no longer written. Not expand–contract: one release switches, and the old dir is removed by D7 on the next `--update` or uninstall. `config.json`, `dev-commands.json` and `manifest.json` stay where they are.
- Manifests older installs wrote carry a `libs` list; D7 keeps reading it. The fixtures that hold today's layout: `tests/fixtures/platform-golden/install/*.txt` (regenerated), and the manifests `tests/install.bats:26,291` build.
- Human-facing paths `~/.coding-crew/lib/tracker/cli.mjs` and `.coding-crew/lib/tracker/docs/<kind>.md` stop existing; D8 replaces every line that names them. Issues already published with the old step keep working until the person's next `--update` removes the dir; the step then fails with "no such file", and the new wording is in the tracker docs they are pointed at.
- Source tree: `{{FRAGMENT:key}}` lines become marker pairs; a PR that edits a fragment or a lib must re-run the renderer (D4 fails otherwise).

## Testing Decisions

- Behaviour over mechanism: B1 and B3 assert what an agent finds on disk and that `cli.mjs config` runs from there; B2 is the only test that reads the renderer's output directly.
- Seams, all existing: bats under `tests/` (`bash scripts/ci-run-bats.sh tests/*.bats`), the golden install tests (`tests/platform-golden-install.bats`), the smoke script (`tests/smoke-crew-afk.bats` stubs the agent CLI). Prior art: `tests/install.bats:223,252` for layout assertions at both scopes; `tests/platform-install.bats:107,123` for the "fifth platform" pattern; `tests/render-skill-shared-fragments.bats:69` for byte-identical fragment prose.
- The npx test pins `skills@1.7.2` and needs network and Node; CI runners have both (bats runs the tracker CLI with `node` already). It is skipped, not failed, when `npx` is absent, with the skip reason printed.
- Prose changes (D8, D9) are checked from the diff, not by grepping rendered text.

## Out of Scope

- Renaming the `codex` platform key to `agents` — needs a manifest alias for old installs; the README paragraph says what the key covers.
- A build branch holding the rendered tree — the README command must be the plain `npx skills add ypxing/coding-crew`, and main HEAD is what `bootstrap.sh` installs today.
- Retiring `install.sh` or `bootstrap.sh` — decide after the npx smoke run has passed and a release has shipped on it.
- Actions workflow support for CLIs beyond `copilot`/`claude` (D12).
- Native plugins and marketplace listings (#444).
- Windows-native claims for the npx route (the tool falls back from symlinks to copies there; untested here; `docs/guide.md` keeps WSL2 as the supported path).
- Following inter-skill dependencies under `npx skills` — the README says `--all`; a partial install that lacks a sibling fails at the host's "unknown skill" line.
