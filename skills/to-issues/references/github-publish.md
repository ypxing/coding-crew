# Publishing under the `github` tracker

Read this when the configured tracker is `github`. It replaces the local file writes in step 6.

**Under a configured `github` tracker**, `publish` (per `github.md`'s `Operation: publish`) creates one GitHub issue per slice via `gh issue create --body-file <file> --label ready-for-agent --milestone <feature-slug>`, where `<file>` is the issue-template body in `SKILL.md` rendered to text — the body itself, not a sidecar, carries the dependency graph for this backend. Write `## Blocked by` entries as `Issue #<n>`, citing the number `gh issue create` returned for each already-created blocker (the lint run before this used provisional numbers — see `SKILL.md` step 6) (the same numeric convention `body-format.mjs`'s `extractBlockedByNumbers` parses) — this is why blockers must still be created before their dependents under this backend too. When step 2 found a PRD, cite it in `## Context Documents` as `PRD: #<n>` using its issue number. The local-only re-run handling (`references/rerun.md`) does not apply: a milestone accumulates issues across runs with no local directory to inspect, so re-running against an existing milestone always adds new issues rather than overwriting; confirm with the user first if this doesn't look like a re-run they intended.
